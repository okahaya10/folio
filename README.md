# Folio

スマホ向けの見積・請求・入金・領収アプリ。ログイン後、会社ごとに分離されたワークスペースを利用します。

## この版の実装
- 会社別ワークスペース、サーバー認可、メンバー招待（7日・単回・メール一致）、スタッフ／管理者／オーナー。
- 見積・請求・領収の下書き保存と発行、複製、一部入金、領収発行。
- 税率別の税抜集計・切捨て、日本語PDF、角印PNG、送付記録、メール本文コピー、CSV・JSON出力。
- D1永続化、R2ファイル保存。会社ごとの状態を楽観ロックで更新し、二重請求・二重入金の競合を防止。
- 初回ログイン時に会社アカウントを作成。本物の取引先情報はサンプルに含めない。

## 起動とビルド
Node 22以上、pnpm。依存追加後はpnpm-lock.yamlを維持。
`pnpm install` → `pnpm db:generate`（スキーマ変更時のみ）→ `pnpm build`。
ローカルD1にはREADMEの元スターター方式に従い生成済みmigrationを一度だけ適用。公開時はSitesが適用。
Sites用D1 bindingはDB、R2 bindingはBUCKET。認証はSitesのChatGPT認証ヘッダー。任意のユーザー入力や通常の公開HTTPヘッダーを信頼する構成でVPSへ直接置かないこと。

## 検証
`python3 tests/isolation_test.py` はSQLの会社分離・所属解除・閲覧専用・楽観ロックを検証。
`tests/domain.test.ts` は税計算、二重請求拒否、入金残額、一部領収、二重領収拒否、スナップショット、日本語複数ページPDFを検証。
PDFの出力は一時領域 `.test-output/` を使用。ブラウザ実機テスト・WebMCP実行テストはこの作業では未実施。

## 他社提供前に確認する境界
この版は動く初期製品。設計書の全SaaS運用要件が完了したという意味ではない。
- 認証はChatGPTアカウント。所有者限定公開中は他社はアクセスできない。外部提供には公開範囲と利用者の認証導線を確認する。
- 初回の所有者限定アクセスで運営者を初期化する。初期化前に公開範囲を広げない。
- D1はPostgreSQLではなくRLSを提供しない。全APIの所属チェックと条件付きSQLで分離。この版の会社状態はJSON集約保存（90万文字上限）で、小規模な試用向け。大量データ向けの正規化・ページング・負荷検証は別途必要。
- 会社作成者は明示的にその会社のオーナー所属を持つ。独立した運営者と会社オーナーの分離・オーナー移譲・運営者の詳細非閲覧モデルは追加実装が必要。
- 利用中／閲覧専用／利用停止は手動管理。自動課金、契約期限、人数・発行数別の料金制限は未実装。
- 初期税入力は税抜のみ。税込切替、複雑な税区分、返金・相殺・値引き、複数請求への消込は未実装。
- オフライン保存、定期バックアップ・自動復元・解約ポリシーは未実装。JSON出力とPDF控えを使えるが、全自動バックアップとは別。
- 入金済み請求の取消は拒否。入金取消・返金の訂正フローは別途追加。
- 法令対応済み・適格請求書認証済みとは表示していない。本人の会社情報・税務運用の確認が必要。

## サーバー移行
Sitesの認証ヘッダーはプラットフォームの保護境界が前提。さくらVPSでは認証とDB・ファイル保存アダプターを置換し、DBレベルのRLSなどを含む分離検証を再実施する。
